# 专业材料：用户提供的 Rubric 跑分流程图

来源：Rubric跑分流程(1).svg，图中标注绘制于 2026-11-10。原图、完整文字摘录分别保存在 source.svg、source-text.md。
以下为原图事实的结构化整理。它不是对当前线上配置的核实，也不是本地调试台实际运行出来的结果。

## 四个环节

1. 固定同一批测试片段。输入包括上文师生对话、当前学生输入、对应教学任务/当前环节。同一 case 的两版使用相同上文，不是完整课堂模拟。
2. 旧版 Prompt 和新版 V2 Prompt 分别让教学模型生成下一轮老师回复，包含口播与板书/组件指令。图中两版 Teaching 均为 gemini-3.8-flash。V2 使用新 SystemPrompt、新任务 YAML，发言话术置空。
3. 裁判模型按对应 Rubric 逐项判断。原图裁判：deepseek-v4-pro，thinking:high。输入是上下文、待评回复与 Rubric；两版使用同一组标准。
4. 按预设规则聚合，比较整条通过率与单项能力表现。图采用 Must-have 否决制示例；其他实验可以预先约定不同聚合规则。

## 九个维度及原图释义

教学类比（帮助理解，不是原图新增判分数据）：同一 case 像同一道题及作答情境；两版回复像两份答卷；Rubric 像各项评分标准；裁判模型像按标准阅卷的老师。逐项检查后汇总整体结果。本图使用达标、不达标、不适用，以及 Must-have 否决制的 PASS/FAIL，不是维度分数的简单加总。

| 维度 | 关注什么 |
|---|---|
| 学生判断 | 识别理解程度与卡点，据此决定追问、提示或直接讲解 |
| 指令遵循 | 遵守教学与输出协议，包括口播结尾、组件调用、结束标记 |
| 数学正确性 | 概念、数量关系、计算正确，结论满足条件 |
| 板书质量 | 关键过程与关系同步可见，不遗漏关键对应 |
| 流程执行 | 在当前环节完成应做任务，按条件推进、切换或结束 |
| 答案保护 | 保留学生独立思考和作答空间，不提前给答案 |
| 讲解质量 | 解释关键原因与易错点，用情境讲明抽象关系 |
| 讲解逻辑 | 承接连贯，前提到结论有依据，不跳步、不矛盾 |
| 语言表达 | 清楚、自然、易懂，减少歧义和不必要负担 |

实际按 case 选检查项。一个检查项 = 维度 + 级别（Must-have / Nice-to-have）+ 可判定标准。
原图示例：“学生明确说‘你继续讲’后，是否直接给出有效讲解？”属于学生判断 · Must-have。
裁判输出 ✓ 达标、× 不达标、— 不适用及各项理由，供定位问题和人工复核。不是直接投票选择哪版更好。

## 汇总规则（原图示例）

- 任意 Must-have 判 × → 整条 FAIL。
- 没有 Must-have 判 × → 整条 PASS。
- Nice-to-have 不决定整条通过 / 失败。
- 整条通过率 = PASS case 数 ÷ 全部 case 数。
- 单项通过率 = ✓ 数 ÷（✓ 数 + × 数）；— 不适用不计入分母。
- 可以按级别或维度分别汇总；单项通过率高不代表整条通过率高。

## case_001：不封闭图形植树 / 讲解环节

输入摘要：从一楼到二楼需 2 分钟，爬到四楼需多久？学生先答 8 分钟，老师已纠正为 3 段、6 分钟。老师追问为什么少 1，学生沉默后说“没事你继续讲”。另外有配合动态文本板书的提醒。

旧版回复摘要：板书明确楼层编号是点、爬楼过程是段、点数比段数多 1。口播解释从一楼出发，然后进入植树例题，让学生先尝试。
V2 回复摘要：解释从一楼出发；板书仅写间隔定义，口播解释间隔；继续问爬到 6 楼有几个间隔，尚未进入植树例题。

以下均沿用原图中的裁判记录，不是本次重新跑分：

| 检查项 | 级别 | 旧版 | V2 |
|---|---|---|---|
| 数学正确性：4 个楼层位置对应 3 段，段数=点数−1 | Must-have | ✓ | ✓ |
| 板书质量：同步呈现点、段和数量差异 | Must-have | ✓ | ×，仅给间隔定义 |
| 学生判断：学生表示不会/放弃后直接有效讲解 | Must-have | ✓ | ✓ |
| 答案保护：进入例题1时保留先作答空间 | Must-have | ✓ | —，尚未进入例题1 |
| 讲解质量：明确楼层位置是点、爬楼过程是段 | Must-have | ✓ | ×，未建立点段映射 |
| 讲解质量：口播清晰、承接自然、不连抛多个不同问题 | Must-have | ✓ | ✓ |
| 讲解质量：学生说继续讲后仍用提问引导思考 | Nice-to-have | ✓ | ✓ |
| 指令遵循：结尾与结束标记符合环节状态 | Must-have | ✓ | ✓ |

原图整条结果：旧版 PASS；V2 FAIL。V2 有两个 Must-have 不达标，数学正确不能抵消必需项失败。

## 实验与结论边界

比较 Prompt 时，尽量固定测试集、教学模型、采样参数、Rubric 与裁判配置。判分与聚合规则应预先约定，重要结论需重复运行并人工复核。
上述示例只能解释这一条 case 的原裁判记录，不能据此宣称新版在所有课堂更差。图中型号仅作来源信息，当前课堂模型以运行配置为准。
