# Rubric 专题面试：备选主问题与条件追问

这是根据用户提供的流程图编写的练习提纲，不是实际公司面试题，也不是本次重新运行评测的结果。默认模拟时供面试官选题，不直接口播全部提纲；用户要求拆题或讨论追问时可以解释。

## 1. 为什么引入 Rubric
主问题：如果要判断新版教学 Prompt 是否更好，你为什么会引入 Rubric，而不是让裁判模型直接选出更好的回复？

- 只说“更客观/更标准”：追问“怎样把‘讲得好’改成一个能依据回复判定的检查项？”
- 混淆标准和裁判：追问“同一套 Rubric 换了裁判模型，结果一定一样吗？为什么？”
- 已说明可解释、可定位：追问“按项检查相比直接选优，还可能遗漏什么？”允许比较取舍，不把 Rubric 宣称为唯一正确方法。
- 判断思路：标准明确检查什么，裁判结合上下文、回复和标准执行判断；判定理由帮助定位问题。标准仍可能不完备，裁判仍可能误判。

## 2. 两版如何公平对比
主问题：同一条学生输入，旧版和新版要怎样组织评测，才能公平比较？

- 只说“同一测试集”：追问“只固定学生最后一句话，但两版上文师生对话不同，还能直接比较吗？”
- 只说“模型相同”：追问“裁判和 Rubric 不同，会给对比带来什么问题？”
- 条件已说全：追问“Sys、任务 YAML 和话术同时变化，效果差异能归因于 Sys 吗？”
- 判断思路：相同 case 上文、学生输入、任务/环节；教学模型和采样配置、Rubric 与裁判配置尽量固定。原图比较的是下一轮回复，不是完整课堂；同时改变多个变量只能讨论整套方案差异，不能单独归因。

## 3. 标准怎样可判定，必需项为何否决
主问题：案例中，V2 的数学结果正确，但板书没有建立楼层“点”和爬楼“段”的对应。按照这份图的规则，为什么整条仍可能 FAIL？

- 只说“板书不好”：追问“你会怎样把这个问题写成可判定的板书检查项？”
- 已说明 Must-have 否决：追问“如果失败的只有 Nice-to-have，整条结果会改变吗？依据是什么？”
- 认为所有项都应设为必需：追问“把每项都设为 Must-have，会怎样影响结果的解释和改进优先级？”这是设计讨论，不假设唯一阈值。
- 判断思路：一个检查项包括维度、级别与可判定标准。原图任一必需项不达标即整条 FAIL；数学正确不能抵消另一个必需项失败。Nice-to-have 不影响整条通过。

## 4. 汇总口径与不适用
主问题：假设某个检查项在 10 条 case 中有 6 条达标、2 条不达标、2 条不适用，按这张图的口径，单项通过率怎么算？请说明分母。

- 把不适用算失败：追问“‘尚未进入该环节’与‘进入后做错’提供的是同一种证据吗？”
- 正确说明 6÷8：追问“单项通过率高，为什么仍可能有很多整条 FAIL 的 case？”
- 已区分单项和整条：追问“如果一版在更多 case 上不适用，只比较单项百分比会遗漏什么信息？”
- 判断思路：单项通过率为达标数÷适用数，例子为 75%；整条通过率为 PASS case 数÷全部 case 数。不同必需项可在不同 case 上失败。两项指标不能互代；同时看适用数量和 case 构成。若没有适用项，应报告无可计算数据，不能当作 100%。这些数字是练习假设，不是原图跑分。

## 5. 裁判可信度与结论边界
主问题：两版出现通过率差异后，你怎样确认差异足以支持结论，而不是裁判误判或样本偶然性？

- 只说“用更强的模型”：追问“你会拿什么证据验证它在这套 Rubric 上判得可靠？”
- 已提人工复核：追问“人工与裁判不一致时，你会如何区分标准含糊和裁判执行出错？”
- 已提重复运行和样本检查：追问“离线下一轮回复的通过率提高，能直接证明完整课堂的学习效果提高吗？”
- 判断思路：检查原始 case、回复、逐项理由和适用性；人工复核分歧、明确边界样例、重复运行并检查样本覆盖。复核方案是面试设计建议，不是声称原图已经做过；不编造可靠性比例、样本数或上线门槛。单条 case、离线片段和完整课堂的结论范围不同。

## 追问原则
只从用户真实回答中寻找遗漏、含混或矛盾，不能先假设他犯错。讲过的依据不要重复追问；肯定要落在具体内容上。除非用户要求讨论题目或答案，否则不说出上面的判断思路，不用暗含答案的追问替候选人作答。
