# Rubric 课堂：按 section 组织 User

默认 Rubric + 方舟流式链路已接入八个 section。一个 section 是一个教学目的，可以有多轮讲解、插问和理解检查；steps 仍是一轮回复里的口播与板书步骤。模拟面试、本地 Qwen 和 Codex 对照路径暂时使用原有整任务方式。

## System 与 User

System 保存角色、讲解方法、输出协议、语音与板书规则。User 由后端根据当前课堂状态组装，不再在每轮展开全课讲稿。

每轮 User 包含：课程标题和简要目录、学生资料、当前 section 的目标和材料、已实际讲过的目标、当前板书、本节最近对话、上一节的简短交接以及尚未回应的学生发言。学生问到后续内容时，补充最多两个相关环节的材料，先回应插问，再衔接当前进度；不能以“下一节再讲”为由拒答。

默认通用要求来自 `content/rubric/user-task.md` 的“内容推进”之前部分；完整文件仍保留课程设计。实际分节任务在 `content/rubric/sections.json` 编辑。界面的任务字段修改通用要求；修改参考材料会作为补充资料发送。新会话保存配置与分节计划的快照，运行中不悄悄替换教材。

这里的 User 是教学任务上下文，不是伪造学生说过的话。学生原始发言与课程安排分开保存。

## 八个环节

1. 开场与全貌：称呼姓名、自我介绍，说出课程标题和三个方面。
2. 固定一个 case：说明共同输入和下一轮回复的评测边界。
3. 两路生成：共享 case，分别生成回复 A/B，并画出分支关系。
4. 裁判与检查项：用答卷、评分标准、阅卷老师的类比分清对象，说明逐项判断。
5. 整条结果：讲清 Must-have 否决制与 Nice-to-have 的边界。
6. 两种通过率：区分统计单位，说明 N/A 不进入单项分母。
7. 原图案例对照：根据原图记录比较楼层案例的两版表现，不提前揭示结果。
8. 收束与证据边界：回顾输入、判断、汇总，说明单个案例不能推出普遍结论。

## 完成与切换

模型在回复尾部报告 `covered_milestones` 和 `section_complete`。这些字段不参与口播，不阻塞首段语音。提出问题等待时，本节不能完成。

只有完整播报的回复才计入已讲目标。后端在下一次 continue 时检查：上一节报告完成、全部目标已有播报记录、没有等待中的问题，以及必要图示已经显示。两路生成环节另外检查三个节点和两条连线。显式跳过另记 skipped，不记为掌握。新学生输入优先在当前节处理，不因为旧回复刚生成完成就抢先跳节。

进入下一节时，后端记录 `section_user_injected` 并组装新 User。前端等首段语音实际开始后建立新页，直接更新板书，不做翻页动画；等待生成由三根头发的明暗轮换表示，不增加等待。模型在同一节输出的 new_page 会被转换为更新标题，不能自行插入整页。模型生成结束、单独一条板书或学生每次发言均不等于切节。

“目标已讲过”不等于“学生独立掌握”。当前覆盖报告来自模型并结合实际播放校验，不是另一套语义裁判或学情评分系统；报告和下一步规划仍不生成。

## 板书组织

当前页聚焦最重要的 1—3 个结论、必要图示和正在讨论的问题。无关的过程、过渡说明和已用完的例子可 remove，或 clear 并指定 keep，只留下仍有用的组件；历史页仍可回看。

新文字追加到末尾，rightOf 只允许接在最后一行右侧，不能把新段落插到已经写过的行之间。旧组件可以原位更新或强调。默认随新内容滚到板书底部，只有明确指读旧组件时才回到对应位置，新增内容后继续跟随底部；手动滚动暂停跟随，点击“跟随讲解”恢复。普通文字不飘入、不晃动，长内容保持字号并滚动。

## 容错与调试

未知、格式不正确或超量的单条板书操作被跳过，其余有效板书和语音继续。缺失阶段信息使用默认阶段；尾部 JSON 损坏但已有可解析话术时保留话术和有效操作，不重播、不把本节提前判完成。没有可用话术或连接失败仍显示真实错误。

运行检查可查看真实 Sys/User、当前 section、完成依据、模型输出及跳过操作的原因。分节测试覆盖未播出不推进、等回答不推进、图示缺失不推进、用户插问不抢先切节；浏览器测试覆盖语音开始时切页、清板保留历史、追加顺序和滚动跟随。

## 参考与边界

设计沿用 learning_task 的任务、资料、milestone、通用规则和进入新环节时的交接思路。原样本路径见 `content/rubric/board-reference.md`；本地实现不代表原平台的完整运行方式。

本地跨节补充材料通过关键词选取，长课还没有全局学情摘要或语义检索。分节减少无关输入，但不能保证首声始终低于三秒；网络、模型、切句、合成和播放都需要实测。
