# AI 一对一内容调试台：产品与实现说明

## 目标

搭建一个可在本机运行、可直接调用模型的内容实验环境，支持两种场景：

- **学习**：讲师进行专业讲解，学生可以插问。讲清关键点后，用口头问题检查判断、理由或应用，根据实际回答补讲或推进。不做独立试卷、计分测验或正式掌握度报告。
- **模拟面试**：面试官主动提问，听取真实回答，并据此追问或切换问题。当前不生成面试报告或下一步学习任务。

核心工作方式是编辑内容、真实对话、检查输入输出、调整内容，再次验证。

## 四项产品能力与一期范围

| 能力 | 一期实现 | 后续工作 |
|---|---|---|
| 全开麦 | 持续收音、自动识别发言起止、自动提交、语音播报、补充入队、在句尾调整后续播报 | 更强的语义轮次判断、原生流式语音、更低延迟与回声鲁棒性 |
| 专业内容 | 独立的内容材料编辑区、可复用内容包、模型结合材料讲解或提问、保留实际输入供检查 | 内容审校、来源管理、版本评审与领域质量验证 |
| 有针对性的一对一讲解 | 显式背景、目标、已有水平、偏好，加上本次实际对话；讲师调整讲解，面试官调整追问 | 更丰富的用户状态及长期记忆机制 |
| 对人的评估与下一步规划 | 页面灰色占位，不生成评分、报告或规划 | 需另行定义评价标准、证据体系、报告和任务规划 |

主动推进是两类角色的交互行为：讲师可分段衔接，面试官主动开场、根据回答追问。它不意味着无人回应时持续不停说话。

## Sys 与 User 的分工

两者是同一次模型调用的两类内容，不要求部署两个独立模型或 Agent 服务。

- **Sys：相对稳定的规则。** 包括身份、交互方式、允许的行为、内容边界、推进与收尾原则。讲师与面试官各有一份可编辑规则。
- **User：本次任务及动态上下文。** 包括目标、专业材料、用户画像、已发生的对话、当前阶段和运行事件。
- **Assistant 历史：模型已生成的回复。** 语音模式还记录实际播报状态；中断后的未播出内容不当成用户已经听到。

学习场景可以使用相同 Sys 更换讲解内容和用户背景；面试场景可以使用相同 Sys 更换岗位、面试方向和候选人背景。

## 本地结构

```text
浏览器：内容编辑、用户画像、语音对话、运行检查
  ↓ 麦克风 PCM 音频 / 用户文字 / 操作事件
本地运行服务
  ├─ 本地语音识别：SenseVoice Small（Whisper base 备用）
  ├─ 上下文组装：Sys + 本次任务 + 材料 + 画像 + 实际对话
  ├─ 模型调用：方舟 DeepSeek 流式 Responses API（本地 Qwen / Codex 可对照）
  ├─ 动作执行：短语流式合成播放、字幕、结构图和板书、等待、继续、结束
  ├─ 本地语音合成：Kokoro 中文男声
  └─ 本地记录：配置快照、对话、播报状态、运行事件
```

默认通过正式方舟 API 调用用户指定的 DeepSeek 模型，密钥仅在本地后端。Codex 是可选对照路径，不提取应用认证令牌。

## 运行规则

1. 新建会话时冻结角色规则、任务、材料、画像和模型配置。
2. 系统发送开始事件，AI 主动开场。
3. 用户持续开麦；语音达到阈值时开始收音，静默约 0.65 秒后形成一个发言片段；新发言不取消正在产生的首声。长发言分段识别后拼接。
4. 运行系统把新的用户输入和已有对话交给模型。默认输出 `steps[{speech, ops}]`、`phase`、`await_user`、`done`、`adaptation`；后端保存合并话术及实际已显示板书。
5. `speech` 以短语流式播报并同步字幕。`adaptation` 只用于调试，不作为对用户的口播。
6. 学习场景中，当模型无需用户回答时，播报完成后可自动继续；连续自动推进设有限制，用户也可关闭主动推进。
7. 面试场景通常等待用户。较长静默只触发一次中性询问，不循环催促或代答。
8. 普通补充发言不取消正在生成的模型请求，而是进入下一轮。手动暂停、新会话或允许的播报打断才取消相应流程；旧请求迟到不得写入新进度。保存实际已播出的完整短语，未播出的内容不能视为用户已听到。
9. 本期结束时只自然收尾，不生成评估或学习规划。

## 个性化与专业性的检查方式

建议以相同主题、不同画像对比实际对话：新手与熟悉者是否获得不同深浅的解释；同一候选人的不同回答是否带来有依据的追问；用户说“太快”“听不懂”“这部分知道了”时是否及时调整。

专业性检查以内容依据为准：模型是否使用材料、是否越出已知边界、是否编造数据或经历、是否把示例当成用户事实。系统记录模型的实际输入输出，供人工复核；“有材料”和“有画像”本身不能证明内容专业或个性化有效。

## 调试页面

页面适配浏览器高度：顶部显示介绍，主体是完整 16:9 板书，左上角当前讲解标题前为小头像，右上角小字标识课程名。底部提供开麦和文字两种输入、语速、课堂控制、字幕及调试链路。聊天记录默认隐藏。收音时彩色声纹随真实音量起伏，识别和提交状态明确显示。

老师按姓名问候，说出本课标题，以第一、第二、第三预告内容，再按顺序讲解。讲清关键点后提出一个理解问题并等待，已答清的点不重复考。板书支持逐步图示和局部荧光笔、下划线、圈选、方框，不提前展示检查问题的答案或后续案例结论。

开麦自动转写，文字输入同样得到语音回答。新发言在老师生成和等待首声时进入补充队列，当前推理不取消、TTFT 不重置。每句结束后检查补充，调整未播出的后续内容。手动暂停或结束可以取消当前轮次。

调试链路逐步显示输入、识别、服务端收到请求、首字和完整回复、音频返回、板书渲染、浏览器实际播放。每一步都有真实状态，失败落在对应步骤。TTFT 独立保留数值，不被完整回复时间覆盖。首声和模型首字分别计时，不能把收到模型结果当成用户已经听到声音。

## 交付与验收边界

提供两类角色默认内容、可编辑内容包、本地记录与导出、开麦和文字输入、打断控制及自动推进逻辑。

自动检查覆盖过期回复丢弃、并发请求、未播出内容的上下文处理、音频编码和自动分句。真实模型、语音合成与识别需要进行实际调用验证；真人麦克风、扬声器回声与浏览器授权必须在实际设备上试用后判断体验。

本地调试原型的响应时间、识别误差和回声处理尚不代表生产课堂效果。后续在保留内容与状态协议的基础上，可以替换模型和语音层，逐步改善体验。


## 当前交互约定

默认 User 姓名 mock 为吴同学；可编辑姓名，开课按名字寒暄，再进入内容。简单寒暄、确认与选择不进板书，复杂学生问题由模型整理后展示。页面给出发言中、已收到、正在回应的显性状态。

主板书聚焦当前的 1—3 个核心点，讲完的无关过程用 remove 或 clear/keep 清除，换主题用新页保留历史。当前推导仍需展开时固定字号，在 16:9 框内滚动；顶部紧凑标题显示当前核心内容，右上角显示页数和已讲页数。每句语音关联操作，只在相应音频实际播放时呈现。支持文本左右/上下排版、逐步结构图、局部强调和翻页回看。已回答的学生发言在完整播报后标记为已处理，继续事件明确要求推进新内容。

中文男声为 Kokoro zm_011，合成基准速度 200，播放默认提高为原速度的 1.20 倍。重读、快慢和停顿可用显式标记控制，不宣称具备原生情绪生成。低延迟优先，3 秒是实测目标，不用空泛确认语充当有效回复。


## 英文播报与板书视觉

英文术语及句子按原文进入英文音素转换，与中文片段按原顺序合成，保持三茅老师的男声音色。需要中文释义时，模型应把释义明确写进话术和字幕；语音层不再把 Rubric、Must-have、PASS 等词替换成中文。流式切句保留完整英文单词，并识别英文句号；音频缓存版本已更新，避免播放旧译读结果。

板书默认无底色文字，普通要点、说明、学生问题不按类型铺彩色卡片。重点使用局部字色、加粗或下划线；仅流程顺序、分支、因果关系保留浅色节点和连线。开课后只留顶部小标题，简单问题用字幕，复杂问题整理后才上板书。


## 课堂语速配置

底部课堂控制区常驻「语速」滑块，范围为原速度的 0.75—2.00 倍，默认 1.20 倍。修改即时生效，包括正在播报和已经预取的语音，浏览器记住用户的选择。保留原男声音高。

实现使用固定基准语速合成，播放端统一调速并保留音高，避免调速触发重新合成或增加首声等待；原有重读、快慢段落的相对变化仍然保留。

## 倾听反馈与教师动作

彩色声纹按真实麦克风说话状态和音量驱动，每动画帧更新，不阻塞语音链路。识别失败会显示未提交。倾听时三根头发变为波浪线；具体肯定学生正确依据时，随话术的 gesture encourage 操作让一根头发变成爱心。支持系统减少动画偏好。

三茅老师是爱穿格子衫的资深 AI 从业者这一虚拟角色。仅首次主动开课自我介绍一次，随后介绍课题与三个方面；中途继续和学生插问不重启开场。

## 分节与板书执行更新

默认 Rubric + 方舟路径已使用八个 section。每轮只发送当前环节的任务、资料、目标及必要上下文，插问可附相关环节的少量资料；模拟面试和本地模型保留原路径。完成标记须结合实际完整播报、目标报告和必要图示回执提交，不能仅凭生成完成推进。

新文字只能追加到末尾；右侧布局只接在最后一行，旧内容可原位更新、清理或高亮。老师讲到哪个组件，视角跟随哪个组件；手动滚动暂停跟随。普通文字稳定出现，下一节 User 注入后在首段播报时直接更新页面，取消整页切换动画。生成中仅三根头发轮换明暗。左上角是常驻的圆脸大耳朵三茅老师，露出一点脖子和格子衫肩膀，没有底框，平时不抖动，主要通过嘴型和脸部表情反馈。右上角保留小课程标识与页码。

模型不支持的板书指令、错误的操作字段单独跳过，有效语音继续；调试记录保留兼容处理详情。可恢复的尾部 JSON 损坏不会重播已生成话术，也不会把未完成环节标成完成。完全没有可用话术或连接失败仍显示真实错误。

鼓励学生时显示三颗向上冒泡的小爱心；生成中三根头发以蓝、粉、青三色轮流亮起，头像本身保持不动。头像整体略向上调整，按包含格子衫肩膀的构图与标题对齐。
